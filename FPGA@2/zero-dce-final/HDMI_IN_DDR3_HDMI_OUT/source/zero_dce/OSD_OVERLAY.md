# 全画面 CNN 参数网格 OSD

`zdce_grid_overlay.v` 直接接在现有 `zdce_video` 曲线流水线之后。KEY2（C23）切换显示，LED2（C18）常亮表示 OSD 开启；KEY1 独立控制 CNN。上电均关闭，20 ms 消抖、长按只触发一次、帧边界切换。

## 画面内容

整个 1920×1080 有效画面划分为 **30 列×18 行，共 540 个区域**，每个区域 **64×60 像素**。从左上至右下与 CNN 输出网格逐一对应。显示一像素网格线，并在每个区域内显示三行参数，例如：

```text
R-0.85
G-0.72
B-0.91
```

R/G/B 分别使用纯红（FF0000）、纯绿（00FF00）、纯蓝（0000FF）文字，每行的通道字母、符号和数值均使用对应颜色。数值为网络真实 Q14 Tanh 系数四舍五入到两位小数，范围 −1.00～+1.00。小于半个百分位的负数显示 +0.00，避免负零。负系数表示提亮，正系数表示压暗，遵循 `x + a*(x*x-x)`。显示转换不改变 CNN 或增强运算精度。

每格文字从局部坐标 (4,8)、(4,24)、(4,40) 开始，使用 5×8 字形加一像素字间距。文字背景局部压暗以保证可读，其余区域保留原来的视频像素，不覆盖整格。网格覆盖最外边缘。

- KEY1、KEY2 都关：完整原视频，不叠加。
- KEY1 开、KEY2 关：CNN 增强视频。
- KEY1 关、KEY2 开：原视频加黄色全屏网格，各格显示 `R--.--`、`G--.--`、`B--.--`，表示没有有效系数，不显示旧数据。
- KEY1、KEY2 都开：增强视频加参数文字及绿色全屏网格；首张参数图未完成时仍为上述等待状态。

这是缩图网格各点的原始 CNN 系数展示，每格显示自己的网格点系数。增强算法仍使用原来的双线性插值，不改为逐格恒定增益。因此格内每个像素实际应用的插值系数可能与文字标示的单个网格点不同。

## 数据、缓存和时序

从 `curve_we/curve_addr/curve_data` 捕获真实输出；写入与主参数图相同的 `job_map_bank`，读取发布后的 `active_map_bank`。只有完整参数图在 VS 发布后才显示，关闭 CNN 即失效，重开等待新图。

显示侧先把 Q14 转成带符号的百分位整数，再转换为十进制数字，共两级转换寄存，随后同步写 RAM，地址和写使能一同延迟。显示专用双缓冲为 2×540×30 = **32,400 bit**，不保存整帧、不增加 DDR 流量。使用常数移位加法转换数值，像素区域坐标由行列计数器生成，避免像素位置除以 60 的组合路径。实际 RAM/逻辑资源以综合映射为准。

视频仍为固定三拍：地址和字形坐标寄存 → RAM 同步读、信息对齐 → 字符合成。HS/VS/DE/RGB 一起延迟，关闭 OSD 不改变延迟。`zdce_video` 总延迟保持 32 拍，板级输出寄存器再加一拍。

## 工程接入

继续使用已有 `zdce_grid_overlay.v` 文件，无需增加另一个 RTL 模块。`zdce_video` 已新增对 OSD `IMAGE_H` 参数的传递。默认 1080p 配置每格 64×60；其它配置要求画面尺寸可被网格整除，每格至少 40×48。

KEY2 约束文件仍为 `hdmi_osd_key2.fdc`，C18 保留原约束端口名 `ddr_init_done`，仅驱动 OSD LED。真实 DDR 初始化为内部 `ddr_cal_done`，各内部复位不使用 LED 电平。若 LED 极性不同，可修改顶层 `OSD_LED_ACTIVE_LOW`。

本次仅修改 source 源码和说明，未改 PDS、原 FDC，未运行 HDL 仿真、综合或布局布线。由用户重新验证字符/参数、区域边界、四种按键状态、连续刷新及 1080p60 时序。



简要说明：

现在 OSD 的 **每个块代表 CNN 输出参数图中的一个位置**，里面包含该位置的 **R、G、B 三个调光参数**。

- 网格共 **30 列×18 行**，左上块对应画面左上区域，右下块对应右下区域；空间上每格约对应原视频 **64×60 像素**。
- **块越亮**：对应通道的参数越负，提亮倾向越强。
- **块接近中灰**：参数接近零，调节较弱。
- **块越暗**：对应通道的参数越正，压暗倾向越强。
- **块偏红**：R 通道比 G、B 通道有更强的提亮倾向；其他偏色同理。它不是原画面的颜色。

这些块显示的是**调节参数，不是实际增加的亮度，也不是网络的置信度**。

实际处理时，网格参数会经过双线性插值，让相邻位置平滑过渡，因此视频中不会按 64×60 的矩形块生硬地调光。OSD 刻意画成块状，是为了看清 CNN 输出的 540 组参数。
