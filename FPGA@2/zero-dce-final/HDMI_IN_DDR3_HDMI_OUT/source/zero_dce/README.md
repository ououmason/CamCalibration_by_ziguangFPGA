## 接入现有工程

1. 保留原工程已有源码和 IP，将本目录 `rtl_files.f` 列出的 8 个辅助模块 `.v` 添加到 PDS；本次新增的是 `zdce_grid_overlay.v`。
2. 顶层继续使用原来的 `HDMI_IN_DDR3_HDMI_OUT_top`（`source/rtl/HDMI_IN_DDR3_HDMI_OUT_top.v`）。CNN 和 OSD 已直接接入该顶层，新增 `key2` 输入；原引脚端口名和 IP 实例名保留，C18 输出改为 OSD 状态，无需切换顶层。
3. 保留本目录 `weights` 的 12 个 `.mem` 文件；它们是 ROM 初始化数据，不能作为 Verilog 编译。ROM 默认路径相对 **HDMI_IN_DDR3_HDMI_OUT 工程根目录**。若 PDS/仿真从其他工作目录读取文件，须调整 core 中的文件参数或工作目录。确认综合确实装载 ROM，不能接受零权重或无法打开文件的告警。
4. 原 PLL、DDR3、HDMI 配置及引脚约束继续使用。新增 CNN 只运行在 `pix_clk=148.5 MHz` 域，不需要新 PLL 或 DDR 端口。
5. 查看原顶层中的 `cnn_busy`、`cnn_curve_ready`、`cnn_cycles_last`、`cnn_range_overflow`、`cnn_frame_drop`。后两个是复位清除的粘滞故障标志，正常连续视频下应保持 0。诊断信号默认不加 keep/debug 属性，需抓取时自行设置，避免无用调试资源。
6. 1080p60 输入时，将 `hdmi_rx_clock.fdc` 作为约束文件加入 PDS（不是 Verilog 源码）；它为 `pixclk_in` 设置 148.5 MHz。若已有正确的显式输入时钟约束，保留一份，避免重复。重新实现后检查输入周期约 6.734 ns，而不是报告中原有的 1000 ns。
7. 将 `hdmi_osd_key2.fdc` 作为约束文件加入 PDS，为新增顶层输入 `key2` 绑定 C23。原 FDC 的 `ddr_init_done` 输出仍绑定 C18，该物理 LED 现显示 OSD 开关状态，真正的 DDR 初始化状态已分离为内部信号 `ddr_cal_done`。

原顶层已实例化 `zdce_ddr_read_adapter`，连接 `vs_reg`、`hs_reg`、`de_o` 和 `o_rgb565`，其输出接 HDMI 输出寄存器；旧的 RGB565 直通输出赋值已替换。CNN 复位在 PLL 锁定且 DDR 初始化完成后，于像素时钟域同步释放。

`zdce_video` 是通用 RGB888 接口，要求 HS/VS/DE 与 RGB 已对齐、VS 高有效，每行 1920 个有效像素、每帧 1080 行。直接使用此接口时不要再添加 adapter 的两拍同步延迟。

## 按键控制

沿用 FDC 中 C22 的 `rst_in` 低有效按键输入，现用于切换 CNN 功能。**上电默认关闭，输出原视频；按一下 KEY1 开启 CNN 并点亮使能 LED，再按一下关闭 CNN 并熄灭 LED。**每次稳定按下约 20 ms 后切换一次，松开也经过消抖，长按不会连续切换。开关在下一帧 VS 上升沿生效，HDMI 同步输出持续运行。

关闭时停止缩图采集，CNN 核与调度器保持复位，不执行卷积 MAC，也不写参数图；清除旧图有效状态，重新开启后使用新采集帧重新计算。曲线参数为零，RGB 数值原样经过固定延迟通路输出；现在 CNN 加 OSD 共固定 32 拍延迟，开关不改变延迟。开启后先显示原视频，待首张新参数图完成并在帧边界发布，再显示增强效果。若 KEY2 已开启，仍叠加全画面黄色网格和无效参数占位文字；要完整原图，KEY1、KEY2 都关闭。

原来闪烁的 `heart_beat_led`（FDC A20）现为 CNN 使能灯，常亮表示已开启。顶层 `CNN_LED_ACTIVE_LOW=1` 默认按低电平点亮。KEY2（C23）独立切换 OSD，LED2（C18）常亮表示 OSD 已开启，默认 `OSD_LED_ACTIVE_LOW=1`；若板卡极性相反可分别改为 0。C18 保留原约束端口名 `ddr_init_done`，仅输出 LED 电平；DDR IP 输出、帧缓冲复位、时序发生器复位和 CNN 复位统一使用独立内部信号 `ddr_cal_done`，不能再用 C18 的 LED 信号复位这些模块。按键均约 20 ms 双向消抖，按下切换一次，长按不连发，显示开关均在帧边界生效。

`zdce_ddr_read_adapter` 和 `zdce_video` 的 `enhance_enable`、`overlay_enable` 为同一像素时钟域的开关请求；`enhance_active`、`overlay_active` 输出帧边界锁存的开关状态；原顶层已完成连接。未修改 PDS 或原 FDC，新增独立的 KEY2 约束文件由用户添加；未运行 HDL 仿真或上板验证。

## 实现的网络

采用资料列表推荐的 **Zero-DCE++**，不是 CVPR 2020 原版 Zero-DCE 的 24 参数图网络。官方 `Epoch99.pth` 共 10,561 个参数，保持 32 通道、全部 7 层和全部跳连；没有用固定增益、伽马 LUT 或人工卷积核代替 CNN。

| 层 | 输入 | 输出 | 激活 |
|---|---|---|---|
| 1 | RGB，3 通道 | x1，32 通道 | ReLU |
| 2 | x1 | x2，32 通道 | ReLU |
| 3 | x2 | x3，32 通道 | ReLU |
| 4 | x3 | x4，32 通道 | ReLU |
| 5 | concat(x3,x4)，64 通道 | x5，32 通道 | ReLU |
| 6 | concat(x2,x5)，64 通道 | x6，32 通道 | ReLU |
| 7 | concat(x1,x6)，64 通道 | RGB 曲线参数，3 通道 | Tanh |

每层严格按 `3x3 depthwise + bias -> 1x1 pointwise + bias -> activation` 执行，边界采用零填充；DW 与 PW 之间不添加 ReLU。卷积核按 PyTorch 的相关运算顺序使用，不翻转权重。

视频路径：

```text
HDMI 输入 -> 原 RGB565 DDR 帧缓存 -> RGB888 展开
                                  |
                                  +-> 30x18 缩图双缓存
                                      -> 7 层 CNN / 特征缓存复用
                                      -> RGB 参数图双缓存，帧边界发布
                                  |
                                  +-> 参数图双线性插值
                                      -> 8 次共享参数曲线流水线 -> HDMI 输出
```

曲线遵循官方代码符号：`x <- x + a*(x*x-x)`。因此负 a 提亮、正 a 压暗，不能再人为反号。8 次迭代使用同一组 RGB 参数，符合 ++ 的参数共享设计。

## 缓存与算力

- 默认网格为 **30x18**，1080p 的缩放步长分别为 64、60；对每个网格中心的 2x2 像素平均，实现无抗混叠的双线性下采样。只保存 30 组水平像素和，不分配 1920 像素行缓存。
- 参数图恢复使用双线性插值，坐标为 `x*(GRID_W-1)/(IMAGE_W-1)`、`y*(GRID_H-1)/(IMAGE_H-1)`，对应 align_corners=True。相位由整数余数累加器产生，插值权重使用 12 位小数和常数倒数近似。
- A/B/C/D 四组 32 通道特征 RAM，DW 先完成一整层，再执行 PW。这样第 5 层可以安全覆盖 D 中的 x4，第 6 层覆盖 C 中不再使用的 x3；没有卷积读写相撞的原地更新。
- DW 临时区最多 64 通道，所有层共用。concat 通过地址选择实现，不复制特征。大型 RAM 不复位、不清屏，且只有同步读端口。
- CNN 使用 **1 个 DW 乘法器 + 8 个 PW 乘法器**，按层、通道复用。参数图四个奇偶分区让每周期可读到四个邻点，无需复制四整份图。
- 全分辨率增强使用 8 级曲线、每级 3 拍，持续每拍一个 RGB 像素；像素流没有 ready/backpressure。
- 参数图插值 5 拍，曲线 24 拍，OSD 3 拍，总计 **32 拍**，原顶层的输出寄存器再加 1 拍。adapter 另将原 `rd_buf` 之前的 HS/VS 延迟 2 拍，以对齐其已有的两拍 DE/RGB 延迟。OSD 在全画面绘制 30×18 网格，每个 64×60 区域显示对应的 R/G/B 有符号参数，保留视频背景。显示双缓冲为 32,400 bit，不增加整帧缓存或 DDR 流量，实际资源以综合为准。
- 系数图只在 VS 上升沿切换；未有有效参数图时用 a=0 输出原像素。使用之前帧估计的参数，正常约两个帧周期的参数滞后。场景突变时可能出现短暂亮度滞后；不额外保存整帧来消除此滞后。
- 原 DDR 仍保存 RGB565，读写各约 248.832 MB/s，合计约 497.664 MB/s 有效像素数据。新增 CNN 不产生 DDR 流量；原有 AXI 控制、DDR 帧选择及读写缓存未重写。

### 1080p@60 调度预算（源码计算，未实测）

148.5 MHz / 60 = **2,475,000 周期/帧**。默认 540 个网格像素：

- DW：`540 * 9 * (3+32+32+32+64+64+64) + 7*5 = 1,414,295` 周期；含每层 5 拍流水排空及写回等待。
- PW 及输出存储/激活：`540 * 1254 + 6 = 677,166` 周期；每个像素的 25 个 PW group 各增加一拍输入流水排空，共增加 13,500 周期/帧。6 个中间特征层保留各一拍最后写回等待，最终层保留 Tanh 地址准备流水。
- 合计 **2,091,461 周期**，约 **14.084 ms**；相对于帧周期约 15.5% 余量。启动、排队和帧边界发布控制另外占少量周期。OSD 仅流水渲染，不占 CNN 运算周期。

这说明计算调度有余量，**不代表布局布线已经达到 148.5 MHz**。持续输出 1080p@60、CNN 每帧更新和实际器件时序是需要分别验证的事项。

按 PG2L100H 的 18Kb DRM、1024x18 / 512x36 等形态估算，新增 RAM/ROM 约 **127 块 DRM**，加原工程历史报告的 21 块约 **148/155 块**，余量不宽。此为按数组组织推算，实际以 PDS 映射报告为准；`pw_bias` 必须保持分布式 ROM，RAM 的物理切分可能改变结果。核心名义存储量约 240 KiB，分块粒度会产生空洞。

CNN 的 9 个乘法器之外还有曲线 48 个、双线性插值 9 个乘法器及少量常量运算。不能把“CNN 9 个乘法器”当作整个新增视频链路的最终 APM 数。最终 LUT/FF/APM/DRM 和 Fmax 均待使用者综合确认。

## 定点与权重

使用 16 位激活（10 位小数）、16 位权重（12 位小数）、32 位偏置（22 位小数）、40 位累加器。DW 输出及中间 ReLU 进行舍入和饱和；Tanh 采用 513 点非负 LUT 加符号恢复，输入步长 1/64、范围 ±8、输出 14 位小数。全分辨率曲线中间像素保留 16 位，最后再输出 RGB888。

`range_overflow_sticky` 捕获 DW 量化或正的中间 ReLU 输出超范围，便于排查实际图像分布。没有做训练数据校准或 QAT，也未测量定点画质误差。30x18 网格比作者常见测试配置更小、横纵缩放比例不同，会改变空间局部增强效果。这里是面向器件资源的部署配置，不是浮点模型逐像素等价结果。

已从根目录用户提供的 `Epoch99.pth` 导出 ROM，哈希和偏移表见 `weights/manifest.json`。更换权重后，在工程根目录执行：

```powershell
python source/zero_dce/tools/export_weights.py ../Epoch99.pth
```

脚本仅依赖 NumPy，不需要 PyTorch，不执行任意 checkpoint 类。遇到参数形状不匹配或超出格式表示范围时直接报错，不静默裁剪权重。更新权重后须重新综合以更新片内 ROM。

默认尺寸经过源码预算选择；不要仅改顶层 GRID 参数就视为支持其他分辨率。thumbnail 要求横纵整除、步长为偶数；map 要求网格宽高为偶数；core 的 16 位地址支持本配置，但更大网格须重新检查地址范围、帧预算和 RAM。建议首先保持默认值。

## 留给使用者的验证入口

按用户要求，本次仅生成源码/初始化文件，以下项目没有代为执行：

- CNN：对照 Python/PyTorch 核验 DW/PW 偏置、零填充、全部跳连、最后三个 RGB 参数及曲线符号；尤其覆盖四边四角。可用 manifest 中的量化格式构造定点参考。
- 视频：148.5 MHz、总时序 2200x1125，每帧 DE=1920x1080，检查连续多帧无吞像素、行长不变、HS/VS/DE/RGB 的固定延迟；检查启动、复位、参数图发布及黑白像素。
- 调度：查看 `cnn_cycles_last` 与预算，确认每帧有新参数图；检查 frame_drop/range_overflow 标志。缺失输入帧时允许沿用旧参数，输出视频仍连续。
- 综合/实现：检查 ROM 装载成功及 RAM 推断；完整原工程布局布线达到 pix_clk 148.5 MHz，并检查原 DDR/IO 时序与跨时钟约束。新增 RTL 不替代原 DDR IP 的仿真库。
- 图像：弱光、过曝、色偏、细小亮点和快速场景切换，评估网格缩小、RGB565 输入量化以及帧间参数滞后的影响。
