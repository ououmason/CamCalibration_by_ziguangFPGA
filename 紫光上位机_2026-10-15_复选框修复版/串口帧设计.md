# FPGA 二进制帧协议（极简版）

## 1. 目标

FPGA 接收二进制串口数据，通过一条统一指令分别开启功能 A、B、C，并读取对应 `data`。

## 2. 帧格式

每帧固定格式如下：

| 字段 | 长度 | 说明 |
|---|---:|---|
| `HEAD` | 1 字节 | 固定 `0x55`，表示帧开始 |
| `CMD` | 1 字节 | 指令：`0x01=A`，`0x02=B`，`0x03=C` |
| `LEN` | 1 字节 | `DATA` 的字节数，范围 `0~255` |
| `DATA` | `LEN` 字节 | 当前功能的数据 |
| `CHECK` | 1 字节 | 校验和：`CMD + LEN + DATA` 的低 8 位 |
| `TAIL` | 1 字节 | 固定 `0xAA`，表示帧结束 |

示例：

```text
55 01 02 12 34 49 AA
```

含义：开启/执行功能 A，`DATA = 0x12 0x34`。

## 3. 指令定义

| `CMD` | 功能 | `DATA` 含义 |
|---|---|---|
| `0x01` | 功能 A | A 的参数或数据 |
| `0x02` | 功能 B | B 的参数或数据 |
| `0x03` | 功能 C | C 的参数或数据 |

建议约定：收到合法帧后，FPGA 将对应功能使能信号拉高一个时钟周期，并锁存 `DATA`。

## 4. FPGA 解析状态机

```text
IDLE
  -> 收到 0x55 -> READ_CMD
READ_CMD
  -> READ_LEN
READ_LEN
  -> LEN=0：READ_CHECK；LEN>0：READ_DATA
READ_DATA
  -> 收满 LEN 字节 -> READ_CHECK
READ_CHECK
  -> 校验正确 -> READ_TAIL
  -> 校验错误 -> IDLE
READ_TAIL
  -> 收到 0xAA：提交指令、更新 DATA、产生 valid 脉冲 -> IDLE
  -> 其他值：丢弃本帧 -> IDLE
```

## 5. 接口信号建议

```text
rx_byte       : 串口接收的 8 位数据
rx_valid      : rx_byte 有效脉冲
func_a_en     : 功能 A 触发脉冲
func_b_en     : 功能 B 触发脉冲
func_c_en     : 功能 C 触发脉冲
func_data     : 锁存的数据
func_data_len : 数据长度
frame_valid   : 合法帧完成脉冲
frame_error   : 帧错误脉冲（可选）
```

## 6. 设计要点

1. `HEAD` 和 `TAIL` 固定，便于同步和丢帧恢复。
2. `LEN` 决定读取多少字节，避免为 A/B/C 分别设计不同帧。
3. `CMD` 只负责选择功能，`DATA` 的具体格式由对应功能解释。
4. 校验只使用低 8 位加法，硬件实现简单；后续需要更强可靠性时可替换为 CRC-8。
5. 接收超时或长度超过缓存容量时，立即丢弃当前帧并回到 `IDLE`。
